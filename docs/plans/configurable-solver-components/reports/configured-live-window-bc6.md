## Observed operations

- Selected the existing accepted Session form, a paired native/configured set,
  4³ cells, 1 m domain, density 1000 kg/m³, disabled viscosity, 0.02 s intervals
  and three requested intervals. Entered an explicit trusted-local manifest,
  caller runtime provenance and model source declaration.
- Clicked **Inspect package (read only)**. The page displayed actual package
  support, input/output role and pinned manifest. Before launch, neither the
  package's child-start marker nor the output namespace existed. Inspection
  started no child and created no run artifact.
- With forcing disabled, clicked **Freeze and run native + configured**. The
  native baseline and configured member each completed four publications:
  constructor plus three accepted intervals. Two real external requests followed
  the native seed. The analytic package required zero authoritative RHS and
  returned zero pressure. This stationary fixture establishes process/control
  custody; the separate nonzero 2³ full/correction oracle cases establish their
  pressure integration evidence.
- Started a fresh stationary package that stalls after actually consuming its
  first configured request. A repeated activation of Start while active created
  no additional set. Clicked the visible **Cancel simulation** control. The owned
  child exited; the native member retained four completed publications and the
  configured member closed Cancelled with constructor plus native seed only.
- Started again with the same package after cancellation. A distinct CPU child
  completed both requested configured calls and then exited. Both members
  completed four publications. Fresh IDs/paths were used, and every previously
  closed artifact remained byte-identical.
- Started another fresh stationary stall package, waited for its actual consumed
  request, then sent the native window's standard WM_DELETE_WINDOW event. The
  existing close/cancel/drain owner closed the configured member Cancelled with
  two publications, drained the child and exited the application with OS exit
  code 0. The window disappeared. All earlier closed artifacts stayed identical. The
  positive `/proc/353008/stat` supplement records state Z and raw wait status0;
  fresh ps and kill-0 also confirm that exact exited process still exists. This
  is positive OS-exit evidence, not a vacuous missing-proc inference, and does
  not claim that Root performed the parent's wait/reaping.

No source hook, second worker loop or runtime supervisor was added for this
exercise. The input packages are task-owned copies of the independently authored
bounded dense pressure fixture, with explicit stationary-RHS and stall behavior;
they contain no training or learned weights. Runtime markers are observed outputs,
not a substitute for the archived typed terminal or actual child-exit probes.

## Retained adverse cases

The first nonzero 4³ launch was statically valid but its native baseline was
numerically refused at fraction `1.0000000000000009` (four f64 increments above
one), before a CPU member started. It retained one constructor publication,
accepted generation/time zero and typed NumericalFailure. The existing fraction
and atomic publication gates were not changed. The
[independent refusal review](configured-native-refusal-review.md) establishes
what the artifact proves; it does not identify an exact roundoff cause or promise
successful acceptance for every declared control combination. This is a concrete
numerical robustness/usability limit, not evidence of accepted candidate success.

Two slow manual stall interactions reached the existing 30 s CPU reply deadline.
They honestly retain RuntimeFailure after accepted native fallback, with three
publications; they are not relabelled as successful Cancelled cases. The later
bounded input sequence performs cancellation before that deadline and verifies
its distinct Cancelled terminal. No process-tree containment or hard Close time
bound is inferred from any observed duration.
