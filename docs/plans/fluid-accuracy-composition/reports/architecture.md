## Three levels of replacement

An implementation contract is concrete and family-specific. The following names are proposed concepts, not new APIs already present.

1. **Stage**: retain current pressure v1. Add a closed typed stage variant only after its discrete method is selected. Inputs borrow immutable accepted/native scratch state and actual interval. Output is tentative native scratch plus diagnostics/witnesses; no direct publication. Stage version fixes equation/operator, units, associations/layout and support envelope. A viscosity stage cannot be swapped independently of a traction-coupled Stokes solve unless the admitted composition establishes compatibility.
2. **Compatible subgraph**: a finite, reviewed mathematical composition such as unified Stokes owns shared geometry, velocity mass M, cell flux B, strain S, boundary lift and stress convention. Candidate replacement returns required native fields and intermediate witnesses or permits host recomputation. The host checks actual equations at the actual interval. Shape-compatible arrays do not establish equivalence. Descriptor ports expose these shared dependencies rather than suggesting arbitrary rewiring is safe.
3. **Whole native family**: a closed facade selects a MAC family or a particle family with their own state, geometry, step and comparison reconstruction. A whole-family algorithm/AI returns tentative native state. Do not convert particles to a universal grid array. Distinct family identities prevent a pressure-only provider from claiming whole-solver support. Start with deterministic classical fixtures to exercise contracts before model availability.

Particle↔grid transfer is a separate visible versioned operator. It declares support, positive mass, mass/momentum budgets, reconstruction, approximation error and energy loss/work. It has its own refinement tests and provenance. No implicit conversion and no promise of exact mass, momentum, energy, incompressibility and reversibility simultaneously. Cross-family pressure comparison uses a defined physical reconstruction/gauge; particle ordering is not persistent physical identity.

### Mandatory request and candidate facts

| Concern | Contract and host responsibility |
|---|---|
| State/discretization | Native family/version, precise association/index ranges, shape/stride/layout, scalar precision, accepted generation, interval input digest, geometry/operator versions and connected components. Validate unknown input/output representations at the boundary. |
| SI and material | Positions m, time s, velocity m/s, pressure Pa, mass kg, density kg/m³, dynamic mu Pa s, kinematic nu m²/s, forces N versus acceleration m/s², integrated flux m³/s versus divergence 1/s. Explicit nondimensional scale/reconstruction if used. Types alone do not prove a plugin used SI internally. |
| Applicability | Actual geometry and boundary type, wall motion, free surface, EOS, viscosity/stress model, kernel/support, capillarity, Re/Mach/scale/feature envelope; exact accepted dt and shortened final interval. Unsupported means typed refusal, never guessed compatibility. |
| Qualification | Host-assembled full residual/constraint checks, finite/range and geometry checks, global/component mass/source budgets, declared momentum/energy/work diagnostics and tolerances with normalization. A pressure residual is not a whole momentum residual. |
| Runtime/provenance | Algorithm/version/source, exact weights and preprocessing/reconstruction digests, manifest, dependency/runtime/device/precision identities where observed; distinguish declared, observed, absent and unavailable. An artifact hash is not proof of physical truth or model training identity. |
| Resource/lifecycle | Payload/allocation caps, permitted iterations/calls, deadline semantics, cancellation points, typed refusal/provider/validation/budget/runtime errors and selected compatible fallback. Avoid synchronous I/O on paint and unbounded evidence materialization. |

Host qualification guarantees only the executable checks it actually evaluates. It cannot establish constitutive correctness, continuum convergence, experimental validity, arbitrary learned generalization or hard realtime. A wrong divergence-free velocity can pass mass/divergence/energy gates. Include operator/time/boundary matched momentum defects and independently qualified trajectory comparisons for accuracy; still retain the model's supported envelope and uncertainty.

### Transaction and failure semantics

For MAC, use existing SimulationSession prepare → apply → qualify → commit. The particle family must provide these publication semantics through its own native state owner/adapter; it does not inherit MAC arrays or become a second outer scheduler/custody store. The closed facade delegates to the selected native owner. A candidate failure cannot change published arrays, time, generation or accepted host history. Stage fallback receives identical immutable input, actual dt and operator; reusing a partially mutated candidate is forbidden. Subgraph/whole retries require all tentative numerical state and provider history to be disposable or covered by tested prepare/commit/abort or snapshot semantics. Only disposable prepared provider state with infallible in-memory adoption may cross the final host commit boundary; all fallible allocation/validation and external I/O must finish first. An uncertain external commit or failed abort terminates the attempt and invalidates that provider instance; retry requires reconstruction from accepted history, verified identity and demonstrated replay/state equivalence; otherwise no retry. Never reuse uncertain state. Inject prepare/abort and pre-adoption transition failures in C1; final local adoption is constructed infallible, not a faultable external commit. Otherwise fail explicitly. The existing caller-owned pressure provider cannot roll back its external caches, RNG, network effects or hidden state; a new stateful provider must declare and test transaction behavior before admission.

Cancellation is cooperative for synchronous in-process calls. A host wrapper cannot preempt a hung provider or generally recover arbitrary panic. Reuse existing process supervision for bounded trusted-local external models; it is not a hostile-code sandbox. Distinguish timeout, uncertain process outcome, invalid candidate and fallback acceptance. Failed intervals publish no accepted numerical rows. Recording occurs after numerical acceptance and cannot undo it; preserve unrecorded accepted tails and reconcile uncertain writes through existing custody rules. Attempt diagnostics are never represented as accepted state.

## Authoritative interactive workflow

G1 introduces an immutable bounded composition descriptor emitted by the existing numerical composition owner. Its canonical ordering/content digest binds native family, finite node kinds, stage order, typed ports, SI/association/layout, geometry/state/boundary dependencies, parameters/operator identity, time/iteration-loop structure and declared fallback edges. No runtime registry or generic arbitrary graph interpreter is needed.

Record node attempts at actual prepare/apply/qualify/fallback boundaries, with interval/attempt/publication identity and descriptor digest. Fields include actual provider, admitted/refused support, request and weights/runtime identities, validation values/limits/units, iteration count, timing scope, and candidate rejected/fallback selected/accepted outcome. Publication association is optional: failed/cancelled attempts have no accepted publication. Reuse the recording owner’s RuntimeTermination/RCT1 pattern, with an additive bounded workflow terminal-attempt variant for attempt ID, last accepted generation (including zero) and distinct attempted next generation, interval and last completed node/diagnostic. Keep it out of accepted-only configured_publication rows. Cold-open retrieves terminal attempt evidence through the existing attempt/archive owner even when no publication exists. Test cancellation before provider execution, after provider return and before commit, including generation zero. Missing timing remains missing. `ProviderReport.total` is pressure-call time, not total workflow time. Capture bounded summaries; detailed residual histories remain optional capped evidence references. Cancellation callbacks and frozen controls cannot manufacture these receipts.

Add explicit descriptor/receipt variants under the existing recording owner (new profile/version chosen during G1). Preserve old RCP2/RCP3/RCT1 readers and their meanings. Old sources show “workflow execution evidence unavailable.” Before rendering, validate bounded representation and interval/descriptor/publication association; reject corruption and stale evidence. Rendering reads a cached projection, never runtime/package/filesystem work in paint. Selecting a live or archived publication selects its exact evidence, not the latest settings.

The native slice has a deterministic egui 2D canvas, stable IDs and rank/lanes for geometry, state, algorithm, qualification and publication; typed ports and edges; explicit time/iteration back-edges and fallback edges; pointer and keyboard selection; visible focus; pan/zoom/reset; collapsible iteration detail; a complete ordered text equivalent; and a details pane with units, dependencies, requested/actual dt, residuals/limits, parameters, timings, provenance and retained-evidence links. Status has text/icons as well as color. Editing/reconnecting is deferred and cannot mutate frozen intent.

[The interactive HTML](workflow-preview.html) is a local authored design aid with sample graphs and no actual telemetry. It is not the delivered native product. G1 acceptance requires an actual native software-display run through start, live selection, accepted/fallback interval inspection, evidence, cancel/close, cold reopen with provider unavailable and identical retained graph inspection. Existing real-egui event/rectangle tests cover pointer/keyboard semantics and cached source-free paint. Browser support, if subsequently selected, is a separate bounded descriptor/receipt consumer in the custom WASM fixture viewer; it does not inherit desktop process, mesh-import or SQLite features.

## Standards and composed-design admission

Coding Standards `0fc92a24279f3a4574c80af0a2f31ea347a21597` applies as recorded in the plan. Contracts are validated at unknown boundaries with always-on checks; evolution is additive and old records preserve meaning. Contract classes are explicit: new in-process descriptor/view contracts are internal-coordinated (producer/all consumers change atomically, no rejected-shape shim); stored descriptors/attempts are persisted with supported profiles and explicit refusal; external provider protocols follow their public-versioned/distributed-independent version policy. No language binding/generator is added by this proposal. Existing public pressure v1 remains unchanged, rather than acquiring a new indefinite compatibility shim. Persistence reuses one custody owner. GUI verification distinguishes actual interaction from headless paint. Accessibility requires semantic/keyboard/text inspection, not a blanket untested compliance claim. The repository output policy keeps logs, screenshots, caches and archives outside Git. Proofs are scoped below the existing reviewed root inventory rather than falsely refreshing historical qualification.

Composed-design review is **applicable** because numerical, provider, persistence and UI responsibilities meet. Complete architecture probe:

| Probe | Admission answer |
|---|---|
| 1. Independent what/who/how/when/where/why | Numerical owner defines methods/applicability; provider computes candidates; Session publishes accepted intervals; runtime supervises external work; recording retains facts; UI inspects selected facts. Scientific verification independently assesses accuracy. Their clocks/authority remain distinct. |
| 2. Required vs accidental interleaving | State identity, actual dt and geometry/operator identity necessarily cross the composition boundary. UI layout, archive storage and runtime manifest parsing must not enter numerical loops. Capture receipts at method boundaries, not a second scheduler. |
| 3. Caller/composition knowledge | Callers choose a supported finite composition and supply intent; they do not know private stencils, force coefficients, archive rows or rollback details. Numerical owners compile descriptors and executable checks. Unsupported composition cannot become a caller obligation to make safe. |
| 4. Representative changes | Changing viscosity formulation touches its numerical owner, compatible contract and qualification; adding graph color touches UI only; new archive profile touches recording/migration plus bounded consumer; new AI runtime touches process adapter/provenance; new native family adds its own owner rather than modifying every state layout. A coupled Stokes change deliberately updates its whole compatible subgraph. |
| 5. Stable boundary vs hidden representation/lifecycle/version | Stage/subgraph contracts expose method semantics, units, versions and support, not private matrix layouts. Candidate lifecycle is explicit. State association needed for a native candidate is an intentional versioned contract, not an allegedly universal abstraction. Archive schema evolution stays with recording. |
| 6. Independent evolution/verification/failure/replacement | Native baseline remains available; fixtures test provider refusal and transaction semantics without a real model. Geometry/operator oracles and UI receipt fixtures are independent. Recording failure preserves accepted-tail semantics. Incompatible subgraphs fail admission, not late graph wiring. |
| 7. Deletion test for new machinery | Delete descriptor → lose authoritative inspectable composition; delete receipts → lose executed/fallback facts; delete view projection → lose bounded cached rendering; delete native-family contract → cannot safely substitute outside pressure v1; delete explicit transfer → conversion losses become hidden; delete version variant → old archives get reinterpreted. No generic registry, second recorder, graph execution engine or duplicate metric store is justified. |
| 8. Inherent complexity and cumulative machinery | Two state families, coupled boundary physics, tentative candidates and durable actual-attempt identity are inherent. Reuse D1 supervision/custody/comparison and finite typed variants to bound added machinery. Begin with one sealed-MAC inspection slice, measure overhead and stop before arbitrary graph editing. |

This probe admits the proposed ownership model for planning. It does not prove implementations satisfy it; G1/C1 integration reviews rerun it against actual changes, especially if extra abstraction appears.
