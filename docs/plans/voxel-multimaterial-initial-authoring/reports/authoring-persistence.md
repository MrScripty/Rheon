# Proposed initial-domain editor and durable boundary

This contract is specific to the proposed two-material voxel method. It does not seed particles, modify an active simulation, reinterpret a recorded preview or add a general sculpting platform.

## Authoritative document and exact conversion

One Initial contents document owns a checked physical grid, stable document ID/revision, one SceneObjectId, captured Water/Air palette entries, and dense u16 cell IDs. ID 0 means Vacuum; the two material IDs bind distinct phase/name/color/reference-density/viscosity values. Never recycle an ID while a live document/history/run references it. The first UI fixes physical palette values to the supported pair; no third material, per-cell density/velocity/temperature brush or editable EOS. Reference temperature can be preserved as provenance without becoming a thermal field.

Origin/spacing are metres; radius is metres; cell indices are integers. Counts and physical sampling density are distinct from rho in kg/m³ and from preview voxels. Initial authoring cells equal the solver's actual cells, not its preview or the particle sample grid. At simulation start, each Water ID becomes f64 F=1; Air becomes F=0; gas fraction is computed as 1-F. Initial MAC velocity is exactly zero. Rho/mu and dual masses are derived by the numerical contract. No rounding, antialiasing, SDF skin or interpolation creates partial initial fractions. Later solver-generated F in (0,1) is retained as numerical interface data and is never snapped back to an ID.

Drafts may be empty or incomplete. Freeze validates **every cell** and all current cross-field constraints; valid authoring does not imply valid solver input. A Vacuum count >0 yields `unsupported_vacuum` with count and a representative cell/slice, plus “Fill domain with Air” or “Paint remaining cells” actions. Unknown IDs, unsupported pair, bad geometry/counts, nonfinite coefficients, new unsupported boundaries/forces or exceeded allocation budgets give their own typed reason, never an ambient-gas fallback. The UI and non-UI constructor use the same domain validator.

“Fill domain with Air” replaces the entire draft once, regardless of slice/brush mask, as one admitted undoable command. It does not establish a recurrent default. A new document may instead start with Air explicitly selected as its initial fill; changing that choice after edits is the same explicit whole-domain command. Remove leaves Vacuum. Air is occupied and carries rho_g V mass per full cell; transparency does not make it empty.

## Small UI and viewport interaction

Use the existing right Scene inspector and one canonical scene selection. Initial contents is one object. Individual cells are transient authoring probes, not SceneObjectIds or retained particle/cell IDs. Selecting Initial contents activates the brush panel and removes force manipulator ownership from the canvas. Retained Inspector selection stays owned by its existing publication identity.

Visible controls: **Add / Remove / Replace**, **Material: Water / Air**, **Radius · m**, **Slice axis / position · m**, **Layer / Volume**, **Undo Contents / Redo Contents**, **Validate / Save / Load**, and **Simulate** with readiness reason. One concise model label says “Two incompressible materials · filled closed box · no surface tension.” Detailed density/viscosity, phase totals and unsupported features belong in a disclosure, not repeated warnings beside every control. Gas visibility is a display toggle with a labelled material legend. Do not add strength/falloff controls to a binary operation; v1 is full-strength hard support.

Layer mode is default: ray-plane picking selects one axis layer using half-open geometry; the circular footprint uses projected cell-center distance in that plane. Volume mode uses a 3D round support centered at the slice hit; the preview shows its complete depth. This uses one brush with two explicit depth masks, not two sculpt engines. Surface targeting and sphere/box primitives are deferred conveniences; the slice is enough to start in empty space and edit interior cells. A visual front clip exposes the slice but changes no cell or edit mask.

| Operation on a targeted cell | Vacuum | Same material | Other material |
| --- | --- | --- | --- |
| Add selected material | Fill it | No-op | No-op; explain “Occupied; use Replace” |
| Remove | No-op | Vacuum | Vacuum |
| Replace selected material | No-op | No-op | Selected material, same occupied volume |

The brush changes initial mass deliberately. Add creates rho_m V, Remove removes it, Replace changes mass by (rho_target-rho_old)V for each changed binary cell. Display phase-volume/mass totals as initial accounting. They are not conservation laws across authoring commands; closed-run conservation begins from the frozen input.

Use the existing camera projection and physical bounds, with independent checked ray/slice intersection. Handle parallel rays, nonfinite input, near-plane clipping, camera inside domain, exact upper faces and anisotropic cells consistently. Do not clamp outside coordinates into a cell, pick from a thresholded mesh or use stale hits. At exact outer maximum, refuse until stepped inward; at internal layer faces use the documented half-open higher-layer rule. Radius never changes because the display or camera zoom changes. A subcell support that hits no center is an honest zero-cell preview.

In brush mode, unmodified primary paints; middle or the existing explicit navigation gestures control the camera only outside an active stroke. Primary orbit remains unchanged when the brush tool is inactive. During a stroke the camera/viewport/slice/mask/operation/material and document base are frozen; a change cancels, rather than bending the edit. Panel changes, resize/collapse, focus loss, pointer loss/exit, context/selection changes or domain changes cancel and consume events until the initiating release. The same terminal frame cannot orbit, select a force or run. Escape and a first Undo during a live stroke cancel it; a second Undo can reverse the previous command.

Spatial samples are converted to world coordinates and resampled by arc length, not one edit per render frame. For fixed-radius continuous segments evaluate the swept round support, avoiding gaps from fast pointer motion; Layer uses its planar sweep. Break any invalid segment and never bridge a missing input interval. Invalid terminal input cancels the entire candidate; do not commit the last valid preview. No hold-to-accumulate behavior or random brush variation exists.

The keyboard single-dab path uses two labelled in-plane center coordinates in Details: Y/Z for an X slice, X/Z for a Y slice, X/Y for a Z slice, all in metres. The current slice position supplies the third coordinate. Radius, Layer/Volume mask, physical bounds, cell predicate and preview are identical to a pointer dab at that world center. Tab reaches both coordinates and a named **Apply dab** button; activating it validates and commits one atomic brush transaction. Escape cancels pending numeric input or a live gesture; no focus change implicitly applies a dab. Invalid coordinates/radius preserve document/history and show their reason. A pointer gesture remains the sole input owner while active, so Apply cannot commit a second operation during it.

## Deterministic atomic undo/redo

Keep the last committed document unchanged while a gesture accumulates a private sparse overlay. Candidate validation/preview may read it, but save, freeze and solver start may not treat it as committed. A valid owned release publishes exactly one transaction containing document/base/result identities, geometry/palette revisions, one command label and ordered unique cell records with full before/after IDs. Coalesce repeated visits within that gesture only. Discard exact no-op cells/empty transactions. Do not inverse-evaluate the brush for undo or reraycast for redo.

Undo applies exact before-values after verifying current expected content; redo applies exact after-values. Document revision remains monotonic even when contents return to an earlier digest. A nonempty new commit after undo invalidates redo atomically; cancelled/no-op strokes, camera movement, selection and Save preserve redo. A whole-domain Air fill is one command and never a list of hidden partial steps. Loading another document intentionally resets the session history; saving does not.

Text fields retain local text undo priority. Contents undo requires the Draft contents context, with a visible named target; selecting a force or a retained result must not undo a hidden contents command. Do not invent force undo to complete this scope. If force commands later join one global authoring history, the integration owner must explicitly migrate routing/order; `history.rs` remains accepted-timeline storage.

Proposed editor-history payload cap is 32 MiB, independent of numerical arrays, candidate memory, immutable input, preview and recording. Charge actual capacities and metadata. A u16 64³ document is 0.5 MiB before overhead; a changed-cell record with u64 index plus two u16 values is 12 bytes before padding/containers. For dense commands choose cheaper bounded chunk/full-document before/after storage. Evict only whole oldest applied commands after a fitting successful commit and expose the retained undo floor. Do not evict history for a gesture that later cancels. An oversized candidate cancels completely; no unrecorded non-undoable edit, partial stroke or hidden budget expansion. This is a resource proposal, not an executed RSS/latency result.

No in-place resampling of a nonempty binary document in v1: preview resolution is freely changeable but simulation/authoring resolution requires a new explicitly initialized document while the original remains saved. Fractional conservative resampling is later work. Do not silently alter initial volume by nearest-ID resize.

## Editable save and immutable run recipe

Reuse existing native JSON, SHA-256, filesystem and SQLite dependencies at their existing boundaries; add no storage framework. Use one bounded versioned editable document encoding with geometry, palette values/IDs, initial cell payload, context/model identity, byte/count limits and digest. Protect binary payload length before allocation; reject malformed/unknown IDs, unknown versions, duplicate identity, overflow, unsupported geometry/pair and digest mismatch before adopting any loaded state. A saved incomplete draft is valid as a **draft**, but retains a not-runnable reason; do not force a saved draft to become physically filled on load.

Minimal save uses a new immutable revision file at a new path with staged write, flush/sync, atomic no-replace publication and directory durability on the supported local filesystem, following the actual existing manifest owner's guarantees. “Save revision” never overwrites a possible existing publication. Load selects a revision. A later save-in-place/recent-project pointer requires its own atomic replacement contract; it is not implied here. Known failure retains old state; uncertain publication preserves evidence, reopens the target and reconciles before retrying. No user-owned file is deleted as fallback. A session undo stack need not persist; label it clearly. Crash recovery guarantees the last confirmed saved committed revision, not unsaved strokes. A recovery journal is out of scope.

At Simulate, require no candidate gesture, validate supported full occupancy, capture an owned immutable initial spec and all numerical/boundary/tolerance/version inputs, preflight combined active allocations, then start the existing worker. A start failure retains the old results. The worker constructs numerical F/rho/mu/masses from the frozen cells; it never reads mutable Draft or the current material selection. Draft editing is disabled during the active worker. After stop/completion, returning to Draft preserves accepted steps and metadata; later edits make a different future input.

Create a new `voxel_material` saved-run variant rather than loosening the existing configured constructor's all-F=1 validator. Embed bounded initial payload in the immutable run recipe (or one verified immutable asset if later required by size); a digest without bytes is not cold-rerunnable. Freeze exact palette values, initial IDs, physical grid, method version, coefficient/flux choices, requested stepping and actual acceptance policy, gravity, wall policy, source/build identity as actually available and retention limits. No emitter, portal, obstacle, configured provider, AI pressure or authored-force input is supported in this first method; a nonempty selected unsupported feature refuses explicitly rather than being ignored. Legacy variants/hashes remain unchanged.

The actual `SavedRunSet`/`SavedMember` consumers are the native entrypoint, `run_sets/source.rs`, `run_set_view.rs`, `comparison.rs`, `comparison_field_view.rs` and `comparison_archive.rs`, with existing configured-comparison tests. M4 updates their coordinated matches/readiness, narrowly: this new voxel variant is inspectable/rerunnable through its own owner but **unsupported for comparison** in v1. Reject comparison capture, load/readiness and field preflight with a typed reason before applying legacy f32 field inventories or byte estimates. The source dispatcher selects the new variant from its explicit supported envelope version/kind; unknown versions refuse. Existing malformed, integrity and I/O failures remain failures and do not trigger broad parser fallback to another owner. No comparison algorithm or analysis format is added.

Cold rerun opens only that saved recipe, verifies the complete input and supported method, and constructs generation zero anew. It is not mid-run restart. Unknown/corrupt/missing inputs do not fall back to current Draft, full liquid, vacuum, particles or constant-density carrier. Reproducibility promise: identical initial bytes and deterministic numerical replay in the declared pinned native executor; cross-platform bitwise identity is not asserted. Across other supported builds, compare the declared numerical tolerances and report provenance.

## Accepted recordings and material visualization

Use existing `StepRecorder`/`RecordingReader` lifecycle/transactions with a new typed voxel-material profile/adapter. Record constructor F, both palette identities/reference properties, geometry and input digest; constructor pressure remains unavailable. Each accepted publication carries F, f64 MAC velocity, appropriately staged pressure, phase volumes/masses, actual dt/generation and numerical acceptance diagnostics including flux closure/continuity defects. Rho/mu may be recorded as named derived fields or reconstructed from F plus the immutable palette, with units and generation explicit; they cannot be an unrelated editable truth. Do not call pressure an end-of-step EOS field.

Retained appearance must display/probe both material fractions, with gas distinguishable from Vacuum/invalid draft and an accurate legend. Use numerical F for phase colors/slices and the captured palette, independent of surface thresholds. Preview downsampling/transparency is appearance only. Budget any extra channels and cached geometry through actual retained-history/renderer limits; failure to render a large surface does not change numerical resolution or material totals. Inspector exposes the selected accepted run/step/field, not mutable draft values; authoring probes are visibly Draft.

Accepted state and durable append are distinct: a failed/uncertain append may leave an accepted but unconfirmed recorded tail, under the existing recorder contract. Do not roll physics back merely to match UI recording status or claim that the inspection database contains complete integrator restart state. Existing cancellation/join owner remains in charge; no second worker, recorder, scene graph or archive store is introduced.
