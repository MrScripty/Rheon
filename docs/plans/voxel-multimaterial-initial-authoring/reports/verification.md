## Numerical tolerances and conservation meaning

The numerical owner and independent reviewer must freeze tolerances from the declared error sources before running candidate outputs. Use pressure RHS compatibility, true residual and actual velocity divergence separately. Compute phase/total mass and dual-continuity residuals directly, with operation-count-derived arithmetic bounds and actual material-density scaling; a relative pressure residual alone is insufficient. Derive explicit viscosity dt from the actual mass/stress stencil bound, and both volume and dual-mass Courant from actual fluxes.

For a closed box with no sources, each reference phase mass must remain its frozen initial mass within the accumulated arithmetic budget. No material clamping, implicit gas refill, unreported mass repair, boundary leakage or resetting the reference each step may pass. A planned new acceptance assertion is not described as a gate the existing constant-density or particle solver already provides.

Interface refinement uses declared grids/dt and an independent translated-interface reference, with a trend compatible with the selected first-order method. Do not announce an order or accuracy floor from one image. Hydrostatic differences are independently computable and must be checked in Pa; selected pressure gauge has no physical effect. Wall reactions mean global momentum need not be constant. Dissipative transport/viscosity and projection do not certify total thermodynamic energy conservation.

If the selected rounding/residual realization cannot pass ordinary supported fixtures without repeated rejection, use the plan's M2 stop/replan condition. Do not use “all rejections are safe” to accept an unusable supported model. Specific coefficient/kernel equivalence may be compared with legacy constant operators, but the complete new conservative step is not expected to equal legacy semi-Lagrangian evolution. Old mode behavior/hashes are protected by their existing focused contracts.

## Native and integration procedure

Before native qualification, record display/session/graphics capability, selected process lifecycle/work limits, state isolation and exact executable/source identity. No synthetic/native-equivalence claim is made. Use existing UI coverage sizes 1250×820 and 900×650 at 100% and 150% as proposed matched states; report actual available scale rather than pretending an environment supports it. Inspect labels, keyboard field navigation, slice placement, cancel/focus and narrow-layout behavior. The first accepted native workload should be bounded and purpose-specific. The implementing owner must predeclare actual cells/steps/recording/array/work limits and no unintended emitter/provider/lab dispatch, then inspect constructor plus accepted results. Do not run a benchmark campaign to accept a brush panel. Existing worker cancellation/join remains responsible for cleanup. Save/open/rerun requires a fresh process and complete data custody; no new mid-run restart promise.

For implementation changes, run affected formatting, strict Clippy, compilation and focused contracts through the relevant default/core/desktop combinations. Broaden only when shared operator/recording changes justify it. Numerical tests/workloads require the authority applicable at implementation time; this plan does not override any existing environment-specific execution restrictions.
