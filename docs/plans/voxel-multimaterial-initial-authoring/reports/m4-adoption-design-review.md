## Stable old-result accounting

Snapshot and check old owned capacities on the UI thread before Worker::start or any output helper, while no old worker/edit can mutate them. Count actual History outer/track slots, frame/Arc metadata and density capacities; every Inspector's raw and decoded selected arrays; result rows/pixels; immutable Request/profile/vector/string owners; Scene force snapshots/values; and relevant collision meshes. Conservative duplicate charging through shared Arcs is safe. It is unnecessary to introduce a general deduplication graph.

The retained viewport frame needs an explicit charge/query: `Viewport.frame` can keep an Arc whose density allocation is not otherwise present in the current App history. The inherited 80 MiB renderer reserve covers face/projected-mesh arrays, **not that density buffer**. Likewise, check current draft collision, retained Request collision and viewport collision Arc owners rather than assuming one pointer represents all three; they can refer to different meshes. Existing CollisionMesh::allocated_bytes exposes the actual owned geometry/BVH vector capacities. Do not count just public vertex/triangle slice lengths and miss its normals/order/nodes.

Native/configured/voxel retained profiles can contain different owned payloads. Include member/difference/force vectors and names, optional boxed provider/deployment/executor strings, attempt strings and retained path storage as applicable. An empty variant is genuinely empty; absence must not be estimated using a current preset. Source reconstruction, digest JSON length and database file size are not proxies for these live capacities. The proposed small nonallocating methods at the existing owners are appropriate. Do not construct a numerical owner or re-decode an old archive merely to estimate its already retained arrays.

A complete old Inspector may contain raw fields plus carrier, particle, configured or voxel decoded ownership. The actual variants include particle diagnostics and force snapshots; configured fractions/pressure, receipt/provider/runtime metadata strings; and its reader's RecordingRun metadata. Count the actual present owner, not a voxel-only estimate for old legacy state. Canonical RecordedStep capacity arithmetic should count field vector capacity, data and text capacities and inline ownership once; the existing voxel helper can reuse it without changing field semantics or schema.

The proposed freeze needs to state its full scope. Holding timeline_step/track/playback and an old selected-frame Arc avoids new `ensure_timestep`/decode selection. It does **not** by itself freeze all Inspector-owned storage: raw field selection clones field names, and ExportFile's path field has an unbounded TextEdit that can grow after a capacity snapshot. The existing Inspector has no independent timestep slider, so no second timeline framework is needed. Proportionate options are to suspend the allocating Inspector/export controls during Pending and show a preparation caption, or explicitly reserve/exclude those UI-only metadata groups consistently with the declared budget. Avoid claiming a complete frozen Inspector capacity while allowing its counted strings to grow. If ExportFile storage is included, its fields are private in `export_ui.rs`; an owner-local capacity method requires an explicitly recorded narrow write-set addition. Do not access it via serialization or invent a guessed string bound.

Similarly, preserve or hold the old Scene context/selected binding while pending, and avoid committing timeline controls' disposable scalar copies back into held App state. Disabled widgets alone do not prove no programmatic clamp/selection work occurs. The simplest pending branch returns the captured old projection and declines old selection/Inspector mutation until acknowledgment or terminal refusal. It should save the original playback intent rather than permanently erase it merely to pause preparation. On no-ack failure, restore/reuse the original values and bindings; do not advance playback by the time spent preparing. Old data must never be dropped just to fit the cap.

The existing 384 MiB/four-publication/128 MiB reserve policy and its egui/GPU/process/SQLite/allocator/unrelated-view exclusions need not change. During Pending, old arrays remain charged in addition to the new Worker. After adoption the captured conservative old-context reservation can remain in the immutable request; releasing old arrays is not permission to rewrite the accepted policy. Four new publication groups still cover the worker's selected raw/decoded pair plus its closed-audit raw/decoded pair. No new cold numerical clone is needed. These are enumerated source/capacity obligations, not measured RSS or latency proof.

## Constructor acknowledgment and poll ordering

The distinction between worker spawn and acknowledgment is necessary: current worker order is append constructor, publish frame0, then Inspector reload/select0. A frame alone can become visible before typed selection succeeds. Read the new worker's exact frame0 without follow-live substitution and require its constructor tag/stamp, plus the typed selected constructor's exact initial-input digest and constructor stamp bound to the pending immutable recipe/run. The typed read must observe a matching raw/decoded selection under its owner lock; a fresh numerical construction or full closed-archive audit is unnecessary for each poll. Do not acknowledge an accepted generation merely because it carries the same initial-input digest.

**Check acknowledgment before terminal/join handling, including when the Worker handle is already finished.** A fast successful run may finish before the UI polls; so may a failure after a valid constructor. Both can still have an acknowledged new prefix that must be adopted according to the contract. An error/cancellation before the typed constructor acknowledgment preserves old bindings. A worker panic or unavailable typed selection cannot be converted into success by spawn/frame existence. Keep the pending request/manifest receipt available until the terminal decision and exact action/path have been reported.

At acknowledgment, move new history, pending Request, Scene binding and playback/track/result presentation together on the UI thread. Do not let the old running_request describe the new history or new rows while textures/frame still use another geometry. Clear/replace old result rows/textures only at that boundary. Retain the new request as immutable; subsequent Draft changes do not reinterpret it. The existing Worker field, scheduler/cancel/close/join paths and one local pending value suffice.

The new poll branch must precede the legacy `Ok(Ok(_)) if cancelled` shortcut. That shortcut currently discards completed rows solely because the flag was later set; it is not truthful for a confirmed completed voxel archive. Use actual voxel outcome/returned error/prefix semantics, with no retry of append, terminal or uncertain manifest publication. Distinguish no output prepared, immutable started intent retained, accepted unrecorded tail, unconfirmed terminal and confirmed failed/completed pinned archive. Use the **pending** attempt's receipt on no-ack failure, not the old retained request's path. Continue joining on close; freezing presentation does not justify detaching a worker.

## Known absence and reachable presentation owners

Known no authored forces is correct for this fixed voxel model and distinct from legacy metadata unknown. The existing retained binding key `(track, Option<digest>)` and `None` data do not encode that distinction. Carry the explicit semantic variant in binding identity as well as display values; otherwise `prepare_scene_presentation` can immediately overwrite the new known-empty binding by calling the legacy `bind_retained_fields(track, None)` path on the next frame. Empty known data must remain read-only and must not masquerade as the current draft force scene. Preserve existing retained model/selection behavior and keep current force feedback owned by Scene.

The actual consumer set includes: App startup refusal, both start/poll branches, sidebar running/preparation captions, narrow global run/cancel strip, close/update early returns, prepare_scene_presentation/selected_frame, timeline's scalar commit path, Inspector routing, Scene context/binding and viewport's retained frame/Appearance query. While preparing, show the pending method/status without using the old running_request as if it described the active numerical worker. Archive/run-set/comparison entry points are already gated by Worker presence; ensure pending entry does not bypass their inactive-page assumption. Appearance/lab refusal must inspect actual retained mode without allocating or mutating a lab to ask the question.

The proposed owner-local helpers are proportionate. Any additional private owner needed for faithful payload accounting should be explicitly added to the exact write set before editing; no numerical/provider algorithm or broad public abstraction is warranted. Fixture literals get only necessary initialization repairs. Keep normal contents launch and saved voxel rerun unavailable in this slice; none of these conditions authorizes a qualification bypass or native exposure.
