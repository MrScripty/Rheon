## Complete composed-design probe

**Applicability: applicable.** The produced artifact is a native two-material voxel workflow, not a set of disconnected operator helpers.

1. **Independent concepts and dimensions.** Numerical owner decides what F/velocity/pressure/coefficients mean and how each step changes them, during run construction/stepping in reusable Rust. Initial-data owner decides valid editable cells and their exact supported freeze conversion, during editing/load/start, independently of rendering. Desktop owns how the person selects/paints/navigates and how a request is composed. Persistence owns file/record publication/reopen, not physical validity; it references validated input/output. Parent/integrator owns when proposal/implementation/exposure is admitted. These concerns change for different reasons.
2. **Necessary versus accidental interleaving.** Fraction, density, mass flux, momentum and pressure must share one candidate generation; splitting their commit would be incorrect. Document revision, gesture identity and before/after bytes must share one edit transaction. Run identity and exact frozen input must stay bound through recording/rerun. Coupling brush events to live numerical arrays, runtime slot IDs, renderer thresholds, current preset names or wall thermal policy would be accidental and is rejected. Method version identifies numerical choices; project codec and run variant identify durable consumer contracts; SQLite envelope version remains separately owned. Supported legacy variants coexist because actual retained consumers exist, not as a speculative shim.
3. **Caller/composition knowledge.** Desktop knows one typed validated Initial spec, one method/capability result, geometry/limits and an immutable run handle. It does not know PCG diagonals, phase-flux closure order, dual-mass allocation or viscosity stencil. Numerics receives constants/fields/gravity, never egui, paths or current scene selection. Recorder receives one stamped publication and immutable input binding, not a second stepper. Composition must know who owns cancellation/join and durable append failure; it cannot hide those obligations behind “Simulate succeeded.” The new SavedRunSet/SavedMember variant also reaches the actual comparison UI/field/archive consumers. Their M4 disposition is typed unsupported before legacy field-inventory/preflight, preserving old comparisons without adding a voxel-comparison feature.
4. **Representative change paths.** Changing a palette color touches initial/visual projection only, not flow coefficients of an old run. Changing density affects new input validation/numerics and corresponding acceptance, not brush rasterization. A pressure preconditioner change stays in pressure/numerical qualification, not the editor codec unless the persisted method promise changes. Changing an undo budget touches history admission/UI feedback, not solver state. A new persistent field touches its canonical producer, typed recorder/consumer and variant compatibility together. Adding vacuum evolution or compressible gas changes the physical model and forces replanning rather than an enum-only edit.
5. **Stable interfaces versus hidden knowledge.** Validated grid/palette/cell spec and stamped accepted fields are stable values. A mutable array alias, Debug parser, preset-name lookup, “surface=None means scalar density,” or caller-supplied unchecked F/rho pair would leak representation/policy. Add only the specific face-coefficient pressure variant, not a general solver registry/graph. The private dual-flux/stress internals remain within the numerical owner.
6. **Independent evolution, verification, failure and replacement.** Data/edit semantics can be tested without a worker. Numerics can be checked against independent equations without egui/SQLite. Project save faults can be exercised without a solver. Actual native/cold-run composition is then a separate acceptance claim. A failed numerical candidate leaves accepted state intact; a failed append has its own recorded-tail status. A replacement fraction method is local to numerics plus its method identity/evidence, rather than duplicated UI logic.
7. **Deletion test.** Deleting the initial-data boundary pushes geometry/ID/freeze checks into UI/load/worker callers, so retain it. Deleting atomic command history duplicates inverse/cancel/redo obligations across gestures, so retain that small owner. Deleting new coupled state/step pushes mass/pressure generation invariants across existing independent carrier/volume owners, so contain them together. Deleting the new weighted pressure variant forces a duplicated PCG or incorrect scalar physics, so retain the variant and reuse the current solver. Deleting the saved variant loses exact cold input; retain it. A new registry, remote process, general schema generator, journal, sparse tree, mesh sculpt engine or third recorder would not remove necessary complexity and is declined.
8. **Inherent and cumulative cost.** Variable inertia, conservative transport, weighted stress, finite precision and immutable replay are inherent to the selected user promise. They are contained in one numerical owner, one authoring document/history, one new saved/recorded variant and the existing native worker/recording/view owners. M1–M2 resolve the difficult new physics before a UI can advertise it. M3–M4 are not substitutes for a real end-to-end voxel run. If this composition cannot qualify bounded Water/Air behavior, reconsider adoption/model rather than accumulating patches or shipping labels.
