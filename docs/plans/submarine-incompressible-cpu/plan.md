## Objective and scope

A native CPU host must eventually generate physically identified velocity, pressure, pressure/viscous forces and moments, and wake history for a fully submerged rigid submarine-shaped body moving forward while increasing world elevation. Begin with fixed or body-frame straight/oblique flow, then prescribe smooth forward/ascent translation; add attitude only after translation passes. Keep numerical verification, solution uncertainty, experimental validation and visual guidance distinct.

This checkpoint owns only documentation in this planning directory and records the parent's bounded acceptance; it changes no numerical source or capture. Jet/aircraft flow belongs to the separate compressible plan. [PR76](https://github.com/MrScripty/Rheon/pull/76), inspected at `4bcdb7f49225cd645a0934953ba7d339ff5e168d`, already combines accepted-step recording and initial periodic ideal-gas S1. Consume its recording contracts later; do not duplicate, edit or merge its source here. Its periodic inviscid S1 does not supply vehicle aerodynamics, viscous jets or submarine water physics.

Scope: constant-density Newtonian fully filled fluid, laminar qualification first, fixed-body boundary and loads, then prescribed kinematics, wake storage, geometric conservation and explicit Tuldok generation contracts. Free 6DOF, propellers/propulsors, cavitation, air/water surface waves, acoustics/compressible water and experimental turbulent-submarine readiness are deferred. No free-surface elevation model is implied: elevation is the body's world Z coordinate in an unbounded-fluid approximation.

## Observed capability and gaps

Main base is `06eb5da`; the [actual API audit](reports/api-gap-audit.md) owns inspected symbols and limitations. Existing sealed MAC projection, box flux, full-box viscosity, static triangle collision, translating collision intervals, reduced obstacle shear, aligned Stokes and tangential plate coupling are useful prerequisites with incompatible scopes. They do not constitute a composed arbitrary-hull external-flow step. In particular:

- A collision hit or tracer barrier does not supply fluid volumes, wall velocity, tensor no-slip stress or conservative momentum exchange.
- Existing sealed obstacle pressure rejects nonzero outer speeds. Existing aligned strain eliminates outer shear under free-slip assumptions; a uniform vector farfield needs a new affine boundary treatment.
- A pressure projection residual is not a trustworthy surface load. The existing [pressure-load counterexample](../../broader-physics-milestone.md) shows biased adjacent-cell traction can pass gauge/work identities.
- Material SPH/emitter sources and visual concentration do not substitute for resolved boundary-layer, wake or rigid-body reaction physics. Generation/time ownership must be supplied with the new composed step.

## Composed-design admission: applicable

1. **Concerns/dimensions:** numerical owner supplies discrete equations on declared geometry at accepted times; geometry owner supplies oriented volume/opening/wall quadrature for that model; trajectory owner supplies prescribed SI kinematics; recorder owns durable publication; Tuldok owns derived guidance; validator owns expectations and acceptance. Each has an independent reason to change and named phase/write set.
2. **Interleavings:** geometry, fields, pose, loads, time and generation necessarily publish atomically for one numerical interval. Recording I/O and visualization are outside that numerical transaction; failure must retain the prior durable capture and report a gap rather than roll back physics. Do not interleave elapsed wall time or requested controls with accepted simulated time/controls.
3. **Caller knowledge:** validated rho/mu, grid/body geometry identity, boundary type/vector, frame/trajectory, requested dt or steady solve settings, payload cap, cancellation, borrowed accepted snapshot, typed refusal. Caller does not assemble stress/divergence, invent pressure traces, synchronize candidate arrays or guess wall response.
4. **Change paths:** boundary policy touches only numerical boundary owner and its verifier/contract; hull geometry touches geometry owner and mesh tests; trajectory law touches trajectory owner and motion oracle; archive storage touches recorder and adapter tests; Tuldok resampling touches exporter/consumer. Changes requiring every owner indicate a contract redesign, not routine duplication.
5. **Stable dependencies:** physical grid/geometry and accepted snapshot are explicit values. Existing sealed/reduced methods cannot be called with hidden boundary overrides. Stage ordering, pressure diagnostic lifetime and native centering are explicit contracts. Version roles: geometry/trajectory identity, numerical method identity and persisted profile version are distinct.
6. **Independence:** validator runs against exported actual fields without importing solver flux/stress/assembly. Recorder can fail without invalidating a numerical acceptance. Numerical owner can be replaced only by satisfying the same physical/frame/rollback contract, not by matching pictures.
7. **Deletion test:** deleting numerical composition pushes conservation/wall/clock reasoning into each host; it contains inherent complexity. Deleting geometry ownership duplicates topology and quadrature between pressure/stress/transport, so retain one owner per supported geometry. Deleting trajectory ownership duplicates pose/time evaluation, so retain it once motion starts. Deleting recording adapter forces consumers to reconstruct native semantics; retain only for actual I7 consumers. Delete speculative solver registries, backend traits, new SQLite schema and visual restart adapters: none are necessary.
8. **Cumulative machinery:** I1 retains one opt-in experimental numerical owner, one native fixture/exporter and one independent validation boundary using existing immutable grid/box metadata. Later geometry/trajectory/persistence are admitted only when their real invariant is required. No generic physics framework, new hosting service, duplicated PR76 recorder or public API burden is justified now.
