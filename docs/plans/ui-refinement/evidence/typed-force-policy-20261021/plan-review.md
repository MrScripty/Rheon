## Minimal API and ownership

`force_run_policy.rs` may own Target::{NativeCarrier, ParticleMaterial,
Unsupported}, Qualification::{Pending, Validated}, one production Pending constant
and one pure check(target, has_authored, qualification). Keep it a desktop module
with narrow visibility; no trait registry, plugin/capability framework, dynamic
evidence service or serialized new field. Existing domain validation/freezing
remains outside this policy. The policy cannot itself establish a valid document,
supported geometry, budget, scientific correctness or recording association.

Meaning of the single presence argument must be explicit: authored metadata is
present, not physically effective. Any Some ForceSnapshot counts, including
Some(empty), disabled objects and zero strength. A legacy None does not. Request
presence is derived once from its authoritative per-track vector; saved-member
None never falls back to draft. SceneUi readiness uses its canonical draft/freeze
path, never the currently displayed Retained document. An empty ordinary draft
continues producing None under the existing launch semantics.

For absent metadata the policy imposes no new force restriction; all ordinary
Request checks still apply. For present metadata, Unsupported refuses regardless
of qualification; otherwise Pending refuses and Validated permits only this force
eligibility decision. Thus the private test-qualified path cannot admit configured
or other unsupported ownership. Error projection should distinguish unsupported
target from pending acceptance with concise visible text; avoid parsing messages
to derive decisions.

## Adapter and composition conditions

- Derive Request target from the actual consumed dispatch: configured/session
  presence takes Unsupported precedence, then material Some maps to
  ParticleMaterial, and only the existing native carrier branch maps to
  NativeCarrier. A future unknown owner must not silently default to native.
- Derive visible setup target from effective SetupWorkflow plus preview material
  mode. Accepted Session remains Unsupported even when retained material mode is
  true. Recompute/check at dispatch after current form updates; do not dispatch a
  stale button-time qualification or independently passed enable booleans.
- `start_configured` and the AI comparison entry explicitly use Unsupported.
  AI must not inherit NativeCarrier merely because its button appears under
  Preview. Retain current viewport/lab force refusal; this slice does not qualify
  transport/provider/free-surface or change those owners.
- `SceneUi::launch_readiness(target)` and Request validation call the same policy
  using the same shared production Pending constant. Recheck before any existing
  output-creating saved-spec/start/rerun path; a check only in Worker::start is too
  late where manifests/directories are allocated earlier.
- Saved native rerun validates its own immutable Request/member snapshots without
  consulting SceneUi or current draft, even if the latter is invalid/unsupported.
  Preserve legacy None behavior, explicit Some(empty) and differing member scenes.
- Keep the existing private cfg(test) force_validation-to-Validated mapping only
  for the reviewed temporary test mechanism. Default false in ordinary literals
  and harnesses. Add no production flag, CLI/environment selector or mutable
  qualification. The later enabling commit removes that bypass/field with its
  fixture updates, rather than replacing it with another hidden gate.

One pure shared policy does not require changing the established session/worker,
numerical adapters, run-set codec, recording, per-track resolver or retained-view
owners. Limit production writes to the new policy module/declaration and existing
main/SceneUi readiness adapters. Test fixture signature updates are mechanical;
preserve unrelated current focus/native work and execution artifacts.

## Later enablement boundary

The future enabling increment is separate: only after the stated native
prerequisites and review may production qualification change and the private
test bypass be removed with equivalent positive/negative production coverage.
Reachable gated authoring/native evidence can precede that increment; actual
force-enabled UI launch is validated afterward on the isolated candidate source
under separate bounded native ownership. This ordering avoids circularity and
does not authorize gate changes or workloads now. Rollback of the preparation
slice restores only its policy/adapters; preserve the sealed prior runtime and
native evidence unchanged.
