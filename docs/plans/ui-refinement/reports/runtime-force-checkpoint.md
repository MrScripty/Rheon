# Gated desktop force custody checkpoint

The desktop now carries one immutable optional force snapshot per track through
native-carrier and particle-material dispatch, Inspector constructor/accepted
recording, saved native intent/load/rerun and retained scene presentation. It uses
canonical backend force/recording APIs, without changing core physics or adding a
second worker/session owner. All production force-enabled launches remain refused
pending bounded desktop runtime/archive validation. Unsupported configured/provider/
session/transport/free-surface paths remain refused.

## Compatibility and presentation

Legacy None uses the existing execution/recording APIs. NativeCarrierSpec and
FrozenSpec v1 JSON bytes/hash are pinned by a literal golden. A force-bearing
FrozenSpec v2 contains the canonical ForceScene and a domain-separated length-delimited
hash over the old spec JSON and canonical exact-bit metadata. Manifest version1
permits independently valid v1/v2 members. ForceMetadata differences distinguish
absence/empty, object order, signed zero, disabled objects, names and units.
Cold binding checks declaration/spec/run force digest; recorder preflight checks
expected fields before create. No automatic historical migration is introduced.

Retained forces project from Request's selected-track snapshot, never the editable
draft. Selection clears when track/document changes even when IDs are reused.
Properties and outline are selectable/read-only; no retained manipulator handles.
Tree/properties and viewport use one cached render-frame track/frame; timeline track
intents apply visually together on the following paint. Legacy absent metadata
remains unknown, while a present empty document is explicitly known empty.
