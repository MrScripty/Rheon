# Configured accepted sessions in the desktop

The desktop's configured controls freeze the existing closed accepted-Session
profile before creating output. A native baseline can run alone or beside one
configured pressure member. Each member has its own `SimulationSession`, fresh
attempt identity, pressure history and recording. The existing desktop Worker,
outer interval loop, model process owner and SQLite recorder retain their
responsibilities. This path does not use the diagnostic comparison Driver as
an integrator.

## Controls and supported contracts

The form captures density, disabled viscosity or a constant Newtonian dynamic
viscosity, one optional constant body force with explicit units and optional
region, requested native prefix and separate workspace limits. Shared launch
controls capture cubic zero-origin geometry, requested timestep and interval
count, pressure settings and recording limits. Disabled viscosity and an
applied Newtonian stage with zero viscosity remain distinct intent.

Package inspection reads and hashes the existing adapter manifest and declared
material without running its interpreter. A paired run requires an explicitly
inspected package, runtime declaration and model source declaration. The
inspection displays supported geometry, physical parameters, history inputs
and full-pressure or pressure-correction output. Editing the inspected locator
or declarations invalidates that capability. The current adapter contract does
not supply checkpoint or training-run provenance; those fields remain absent.

Freeze captures a real rest constructor and immutable future controls. It
performs no numerical advance, model startup or artifact publication. Launch
validates the frozen host and supported desktop profile before creating its
output directory, publishes immutable intent, then starts the existing Worker.
Runtime startup revalidates the exact package pins. Model-specific input and
output choices remain limited to the declared adapter contracts; a different
physical stage or interpretation requires separate qualification.

## Accepted execution and failure custody

`ConfiguredTrack` composes `SimulationSession` with the existing accepted CPU
provider. The Session owns actual timestep selection, current RHS, accepted
history, pressure qualification, native fallback and publication. Native seed
intervals do not fabricate an external request. Every actual provider call
captures its authoritative request stamp and process outcome separately from
the core pressure receipt. A support decline before method entry has no
invented runtime observation.

The existing model process and Worker share the same cancellation flag and
child slot. A failed numerical interval publishes no accepted row. Operational
runtime failure can first produce an accepted, host-qualified native fallback;
the Worker records that publication and terminates the member with the actual
runtime cause. A core quality rejection can retain a healthy runtime for the
next request, whose prior is the pressure actually accepted by the Session.

Constructor capture and accepted-row append occur while the Worker retains
the recorder. Terminal handling uses RCT1 and the actual accepted snapshot,
including any unrecorded accepted tail or next unaccepted request. Known
failure causes remain sticky if cancellation arrives later. A terminal write
failure is reported as unconfirmed; it is not presented as a closed member.
Human detail is visibly truncated to the codec's byte budget, with typed
dispatch and complete invalid-payload digests retained independently.

## Saved inspection and rerun

Finished members close the existing recorder before pinning their exact
archive in a new immutable revision. Cold opening uses the existing configured
archive resolver and typed recording codecs; it does not resolve or start a
model. The inspector presents core acceptance, optional runtime observations
and terminal declarations separately. An absent observation does not establish
that no request was dispatched. Full audit checks available associations and
does not reconstruct an unrecorded tail.

A valid archive with no committed numerical rows still permits header and
terminal inspection. It supplies no numerical selection or selected-field
export. A Ready member may have a failed or cancelled terminal outcome; Ready
describes artifact custody rather than successful completion.

Rerun validates the saved host first, creates a new output root and fresh
member attempts from zero, and retains the exact previous revision digest as
its parent. Prior run IDs are excluded. It neither resumes an archive nor
overwrites the original files. A missing or changed package can therefore
produce a new failed-start attempt while the old archives remain cold-readable.

## Validation scope

Production Worker contracts use the actual App launch path, existing
`ModelProcess`, Session and recorder. They cover full-pressure and correction
packages, an independent hydrostatic field oracle, consumed-request
cancellation, failure disposition after late cancellation, constructor capture
failure, changed-host refusal and cold inspection with the package hidden.
Fresh reader subprocesses have no model runtime on PATH; the parent test
process remains alive, while its numerical/runtime/writer owners are drained.
Separate archive contracts establish producer-process-exit custody. These
fixtures establish integration behavior, not learned accuracy or performance.

Configured shared comparison and a native-window workflow require their own
consumer integration and final-source evidence. Component test receipts retain
their exact source subjects; this document does not transfer earlier receipts
to a later composed Git revision.
