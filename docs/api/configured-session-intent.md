# Frozen configured Session intent

The desktop `run_sets::configured` module stores a bounded declaration for a
fresh, rest-state, sealed full-liquid `SimulationSession`. Its explicit
`configured_accepted_session` spec and `configured_accepted_session_set` set use
schema2. Existing native carrier schema1 and its readers/digests retain their
original meaning. This format neither restores a numerical checkpoint nor runs
a provider.

`FrozenConfiguredSpec::capture_constructor` checks the actual constructor
snapshot and captures its immutable `SessionConfiguration`, grid, native method,
logical memory limits, boundary workspace limit, quota and carrier/volume
identities. Only actual constructor state with zero velocity/tracer, full
fractions and no accepted interval/receipt is accepted. Equal represented and
carrier density is an explicit restriction of this initial profile. The logical
constructor memory limit remains distinct from an owner's internal budget split.

The caller separately declares `ConfiguredFutureIntent`: constant requested
interval size/count, force values/units/regions, volume controls, disabled or
constant Newtonian viscosity, workspace budgets, recording budget and constructor
capture. Pressure intent is native-only or a declared native prefix followed by
an exactly pinned configurable package. The latter includes its minimum prefix,
content identity and a runtime-owned deployment locator. A zero coefficient with
an applied Newtonian stage remains distinct from disabled viscosity. Actual dt
can later shorten under the existing numerical gates; this document is requested
intent, not an observed execution receipt.

`ExecutorDeclaration` identifies the host separately from model identity.
Unspecified build provenance stays absent; a declared source string/hash is not
authentication, build reproducibility or model accuracy. Before execution,
`validate_execution` compares the actual host declaration. The runtime must also
resolve actual package bytes, compare the expected identity and enforce the
loaded package's physical/context support. A project-relative deployment locator
and an external absolute locator have separate bounded path contracts. Cold
intent opening never resolves either or loads model code.

`create_session` constructs fresh rest state through the existing Session owner.
It executes no interval and does not itself grant runtime admission. A composer
must drive every requested control from the frozen intent, preserve actual
shortened times and accepted/fallback observations, and retain failures without
substituting current controls. Reruns require new identities and attempt paths;
there is no resume operation.

Specs bind version/kind, constructor and future controls to a SHA256 digest.
Finite scalar serialization preserves signed zero. Sets record explicit baseline
and variant differences, immutable member specs, an optional exact parent digest
and separate attempt declarations. `save_new` refuses replacement and uses the
existing bounded publication owner. Readers reject unknown versions, fields,
kinds, duplicate keys and altered digests. Opening historical intent does not
compare it against the current host or require the old deployment to exist.

The `configured::archive` child binds an actual constructor to the frozen spec
in the existing recording header. `ConfiguredRunAttempt::pin_closed` closes the
custody boundary only after typed header/publication validation and matching
before/after file hashes. The composer must close its writer first and protect
immutable local paths throughout pinning and inspection. A caller-assigned
`FinalizedArchive` alone grants no readiness.

`archive::open_member` explicitly reports NotRun, Missing, Incomplete, Unpinned,
Unsupported, Invalid or Ready. Historical opening creates no Session/provider or
runtime and never resolves the deployment. Ready requires exact constructor,
source, geometry, recording budget, intent digest and host declaration; a known
terminal accepted tail; actual applied viscosity and native-prefix/provider
policy; full configured profile validation; and the pinned artifact hash. A
completed run must cover the entire requested horizon. Failed/Cancelled outcomes
may retain an explicit unrecorded accepted tail within that horizon. Missing
accepted-generation knowledge cannot become Ready. Actual owner-provided interval
starts and shortened dt are retained; cold validation permits dt at most the
requested value rather than reconstructing start by subtraction.

Cold inspection compares the observable physical/identity facts. Force controls,
requested scheduling and package execution remain producer declarations; neither
an RHS digest nor a header proves those future operations independently. Generic
or native archive validation cannot replace the configured typed audit. The new
profile is inspection evidence and cannot be used as a restart checkpoint.

Nine configured contracts and17 existing native saved-set contracts exercise
constructor fidelity, native implementations, immutable publication, schema
separation, bounded declarations, executor/package drift, historical opening,
explicit differences, unknown kinds/fields, duplicate keys and tampering. These
checks, plus eight real archive binding contracts, do not establish complete A4 workflow acceptance, native-window
interaction, package execution, learned-model parity or performance.
